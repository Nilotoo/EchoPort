EchoPort · Lua 插件 / Plugins

EchoPort 插件开发手册

用 Lua 5.4 给 EchoPort 添加自己的逻辑：监听播放/搜索/下载事件、注册动作与快捷键、读写配置、弹出界面提示。无需编译；插件是按文件名排序加载的本地 Lua 文件。也可以把逻辑编译进 Rust，通过 Plugin / PluginRegistry 扩展点接入。

1. 能做什么 / 三种扩展方式

方式适合改动后如何生效
config.lua主题、快捷键、启动页、音量、下载/缓存等设置设置 → 重新加载脚本
plugins/*.lua事件钩子、自定义动作、快捷键回调、通知/日志 —— 无需编译设置 → 重新加载脚本
Rust Plugin编译进应用的插件（性能敏感、需要访问应用内部类型）重新构建应用

一个 Lua 插件能做到的事情：

  • 在播放开始/结束、搜索完成、下载完成、曲库扫描完成、暂停/继续、应用启动时执行逻辑；
  • 注册自定义动作（出现在设置页，可绑快捷键）；
  • 绑定按键到内置动作、自定义动作或任意 Lua 函数；
  • 触发播放命令、搜索、打开链接、导入链接、设置音量；
  • 弹出应用内提示、写日志、读取当前曲目与运行路径。
没有网络 API：echoport.* 不提供 HTTP 请求；插件运行在 UI 线程，应保持轻量。Lua 标准库完整可用（含 io/os），但阻塞操作会卡住界面，应避免。

2. 文件位置与加载顺序

平台配置插件
Linux~/.config/echoport/config.lua~/.config/echoport/plugins/*.lua
macOS~/Library/Application Support/echoport/config.lua…/echoport/plugins/*.lua
Windows%APPDATA%\echoport\config.lua%APPDATA%\echoport\plugins\*.lua
  • 顺序：先加载 config.lua，再按文件名排序加载 plugins/*.lua（01_a.lua 先于 02_b.lua；隐藏文件跳过，不递归子目录）。
  • 隔离：每个插件文件独立执行。某个插件语法错误或运行时报错，只产生一条 <文件名>: <错误> 警告，其他插件继续加载。
  • 一次性：每个文件只执行一次；用 echoport.on / actions.add / bind 注册的回调会在之后的事件中调用。
  • 重新加载：设置 → 重新加载脚本会重建整个 Lua 状态并重新执行所有文件；Lua 全局变量会被清空。
  • 失败保护：如果重新加载时 config.lua 报错，会保留上一次成功的配置和插件。设置页最多显示 100 条脚本警告。
  • 线程：所有 Lua 回调在 UI 线程同步执行——不要阻塞、不要长循环、不要网络/重型 IO。

4. 插件文件格式

插件就是普通的 Lua 代码块（不是模块，无需 return）：文件被加载时立即执行一次，注册回调后结束。推荐结构：

-- plugins/my_plugin.lua
-- 1) 文件顶部做一次初始化（日志 / 局部状态）/ one-time setup
local plays = 0

echoport.log("my_plugin loaded on EchoPort " .. echoport.version)

-- 2) 注册事件钩子 / register event hooks
echoport.on("track_start", function(track)
  if track == nil then return end       -- 字段可能为 nil，务必判空
  plays = plays + 1
  echoport.notify("♪ " .. track.title .. " — " .. track.artist)
end)

-- 3) 注册自定义动作 / register custom actions
echoport.actions.add({
  id = "my_stats",                      -- 必填、唯一
  title = "播放统计 / Play count",      -- 必填
  run = function()
    echoport.notify("本次会话已播放 " .. plays .. " 首 / tracks played: " .. plays)
  end,
})

-- 4) 绑定快捷键 / bind a key
echoport.bind("Ctrl+Alt+P", "action:my_stats")

文件内可以用 local 保存状态（重新加载时清空），也可以定义辅助函数；不需要 module() 或返回表。一个文件建议只做一类事情，便于排查。

5. 事件

用 echoport.on(事件名, function(...) end) 注册；同一事件可注册多个回调，按注册顺序执行（config.lua 先于插件）。

事件名回调参数触发时机
startup—应用启动完成
track_starttrack 表开始播放
track_endtrack 表当前曲目播放结束
search_donequery 字符串多平台搜索完成
download_donetrack 表、path 字符串下载完成
library_scannedcount 数字本地曲库扫描完成
playback_paused—暂停
playback_resumed—继续播放

track 表

{
  id = "youtube:abc123",          -- 稳定的曲目 id
  title = "曲名 / title",
  artist = "艺术家 / artist",
  album = "专辑",                  -- 可能为 nil
  platform = "youtube",            -- local|spotify|apple_music|netease|soundcloud|bilibili|youtube
  duration = 215.0,                -- 秒，可能为 nil
  url = "https://...",             -- 来源页面，可能为 nil
  local_path = "/music/x.mp3",     -- 仅本地曲目，可能为 nil
}
echoport.on("track_end", function(track)
  if track ~= nil then
    echoport.log("track_end: " .. track.title)
  end
end)

echoport.on("download_done", function(track, path)
  if track ~= nil then
    echoport.toast("已保存 / saved: " .. track.title .. " -> " .. path)
  end
end)
回调里的 Lua 错误会被捕获：记录一条警告并写日志，不会中断其他回调或插件。所有参数可能为 nil，请总是判空。

6. 自定义动作

echoport.actions.add({
  id = "focus_mode",                 -- 必填：唯一 id，用作 "action:focus_mode"
  title = "专注模式 / Focus mode",   -- 必填：设置页显示名
  description = "音量 30% 并暂停",   -- 可选
  keys = "Ctrl+Alt+F",               -- 可选：字符串或字符串表，自动注册键位
  run = function()                   -- 必填：动作主体
    echoport.set_volume(0.3)
    echoport.command("play_pause")
    echoport.notify("专注模式已开启 / focus mode on")
  end,
})
字段要求说明
id必填非空且唯一；重复 id 时后定义者生效并记录警告
title必填缺失时用 id 代替并警告
description可选字符串
keys可选字符串或字符串表；无效键位产生警告
run必填函数；可被键位、echoport.command("action:<id>") 或设置页触发

7. 键位绑定

echoport.bind("Ctrl+Alt+N", "next")            -- 内置动作
echoport.bind("Ctrl+Alt+H", "action:hello")    -- 自定义动作
echoport.bind("Ctrl+Alt+D", function()         -- 任意函数（自动包装为隐藏动作）
  echoport.notify("自定义绑定 / custom binding")
end)
  • 修饰键：Ctrl Alt Shift Cmd（Windows/Linux 上 Cmd == Ctrl），大小写不敏感。
  • 内置动作：play_pause、next、previous、seek_forward、seek_backward、volume_up、volume_down、toggle_queue、toggle_favorite、toggle_shuffle、cycle_repeat、open_search、open_settings、open_home。
  • 同一个按键组合重复绑定时，后注册者生效并记录警告；输入框聚焦时快捷键被抑制。
  • 绑定到尚不存在的 action:<id>：所有文件加载完后统一校验，不存在则忽略并警告（支持同文件内先 bind 后定义）。

9. 完整示例插件

把下面内容保存为 <config_dir>/echoport/plugins/example.lua，然后在设置页重新加载脚本即可。它演示：播放提示、会话内历史、自定义动作、快捷键、日志。仓库里也有可直接使用的 examples/plugins/example.lua。

-- EchoPort 示例插件 / example plugin
local history = {}

echoport.log("example plugin loaded, EchoPort " .. echoport.version)

-- 曲目开始播放时提示，并记住最近 20 首 / toast + keep last 20 titles
echoport.on("track_start", function(track)
  if track == nil then return end
  echoport.notify("♪ " .. track.title .. " — " .. track.artist)
  table.insert(history, 1, track.title)
  if #history > 20 then
    table.remove(history)
  end
end)

-- 搜索完成时写日志 / log finished searches
echoport.on("search_done", function(query)
  echoport.log("search finished: " .. tostring(query))
end)

-- 自定义动作：显示最近播放 / custom action: recent tracks
echoport.actions.add({
  id = "recent_tracks",
  title = "最近播放 / Recent tracks",
  description = "Example plugin history action",
  keys = "Ctrl+Alt+L",
  run = function()
    if #history == 0 then
      echoport.notify("还没有播放记录 / nothing played yet")
      return
    end
    local shown = {}
    for index = 1, math.min(#history, 5) do
      shown[#shown + 1] = history[index]
    end
    echoport.notify("最近 / recent: " .. table.concat(shown, " | "))
  end,
})

-- 绑定函数到快捷键 / bind a function to a key
echoport.bind("Ctrl+Alt+G", function()
  local track = echoport.current_track()
  if track then
    echoport.notify("正在播放 / now playing: " .. track.title)
  else
    echoport.notify("还没有播放 / nothing playing")
  end
end)
关于“桌面通知”：EchoPort 提供的是应用内 toast（echoport.notify），没有专门的系统桌面通知 API。由于 Lua 标准库完整，技术上可以用 os.execute("notify-send ...") 调用外部程序，但它会同步阻塞 UI 线程且依赖平台，不推荐；需要时请谨慎、自行测试。

10. 安全与限制

  • 不是沙箱：配置文件与插件以你的用户权限在本机执行，拥有完整 Lua 5.4 标准库（含 io、os、load）。只安装你信任的脚本。
  • 不联网：echoport.* 不提供网络 API；open_url 只是交给浏览器/系统打开。
  • UI 线程：所有回调同步运行，禁止阻塞（长循环、os.execute、大文件 IO 会冻结界面）。
  • 警告上限：设置页最多显示 100 条脚本警告，超过后折叠。
  • 隔离：每个插件文件独立执行，单文件错误不影响其他文件；插件不能覆盖用户的 config.lua 设置。
  • 无热重载：重新加载会重建整个 Lua 状态（全局变量丢失），不支持只重载某个插件。
  • 重复定义：动作 id 重复时后定义生效并警告；按键重复时后注册生效并警告；无效键位/事件/动作只警告不崩溃。

11. Rust 扩展点（编译进应用）

需要更高性能或访问应用内部类型时，可以实现 echoport::scripting::Plugin trait 并注册到 PluginRegistry。它和 Lua 事件共享同一套 ScriptEvent。

use echoport::scripting::{Plugin, PluginHost, PluginRegistry, ScriptEvent};
use echoport::state::Command;

struct AutoShuffle;

impl Plugin for AutoShuffle {
    fn id(&self) -> &str {
        "auto-shuffle"
    }

    fn on_event(&mut self, event: &ScriptEvent, host: &mut PluginHost) {
        if let ScriptEvent::TrackStart(track) = event {
            host.notify(format!("now playing: {}", track.title));
            host.dispatch(Command::ToggleShuffle);   // 下一帧生效 / applied next frame
        }
    }
}

// 在 EchoPortApp 初始化时注册一次 / register once at startup
let mut rust_plugins = PluginRegistry::with_sender(tx.clone());
rust_plugins.register(Box::new(AutoShuffle));

// 事件分发点 / event dispatch point
rust_plugins.fire(&ScriptEvent::TrackStart(track.clone()));
接口说明
Plugin::id() -> &str唯一 id；重复注册时后注册者替换前者并记日志
Plugin::on_event(&mut self, &ScriptEvent, &mut PluginHost)UI 线程同步调用；不要阻塞；Rust panic 不会被捕获（Lua 会）
PluginHost::dispatch(Command)派发应用命令（echoport::state::Command），下一帧生效
PluginHost::notify(text)应用内提示（等价于 Lua notify）
PluginRegistry::new() / with_sender(tx) / set_sender(tx)创建注册表并连接事件通道
register / fire / plugins / is_empty / len注册、分发、查询

Lua Scripts 不是 Send（Lua 状态绑定线程），请放在 UI 线程；Rust PluginRegistry 与插件本身是 Send 的。

12. 故障排查

现象处理
插件没加载确认扩展名是 .lua、位于 plugins/ 目录、不是隐藏文件；看设置页 warnings 里的 <文件名>: <错误>。
syntax error检查 Lua 语法（end、逗号、引号）；该文件被跳过，其他插件照常加载。
事件没触发事件名拼写（见第 5 节，下划线小写）；事件只在对应应用状态变化时派发。
动作没出现在设置页actions.add 缺 run 或 id 会被拒绝并警告；看 warnings。
快捷键无效输入框聚焦时被抑制；检查动作名；重复按键以后注册者为准。
重新加载后状态丢失Lua 全局状态会在重载时清空；需要持久化请用 echoport.paths.data 自行写文件（谨慎、非必需）。
界面卡顿回调里不要阻塞或长时间运行；重活应拆成短任务，或改用 Rust 插件的后台线程。

EchoPort plugin development manual

Add your own logic to EchoPort with Lua 5.4: listen to playback/search/download events, register actions and shortcuts, read the configuration, show in-app toasts. No compilation needed — plugins are local Lua files loaded in file-name order. Logic can also be compiled into Rust through the Plugin / PluginRegistry extension point.

1. What you can build / three ways

WayGood forApply changes
config.luatheme, shortcuts, startup page, volume, download/cache settingsSettings → Reload scripts
plugins/*.luaevent hooks, custom actions, key callbacks, toasts/logging — no build stepSettings → Reload scripts
Rust Plugincompiled-in plugins (performance-sensitive or needing internal app types)rebuild the app

A Lua plugin can:

  • run logic on app startup, track start/end, search completion, download completion, library scan completion, pause/resume;
  • register custom actions (listed in Settings, hotkeyable);
  • bind keys to built-in actions, custom actions or arbitrary Lua functions;
  • trigger playback commands, search, open a link, import a link, set the volume;
  • show in-app toasts, write logs, read the current track and platform paths.
No networking API: echoport.* exposes no HTTP requests; plugins run on the UI thread and must stay cheap. The full Lua standard library (including io/os) is available, but blocking calls freeze the interface — avoid them.

2. File locations & load order

PlatformConfigPlugins
Linux~/.config/echoport/config.lua~/.config/echoport/plugins/*.lua
macOS~/Library/Application Support/echoport/config.lua…/echoport/plugins/*.lua
Windows%APPDATA%\echoport\config.lua%APPDATA%\echoport\plugins\*.lua
  • Order: config.lua first, then plugins/*.lua sorted by file name (01_a.lua before 02_b.lua; hidden files skipped, sub-directories not descended into).
  • Isolation: each plugin file runs once in its own protected execution. A syntax/runtime error in one plugin produces a <file>: <error> warning and the other plugins still load.
  • One-shot: each file executes once; callbacks registered with echoport.on / actions.add / bind are called later.
  • Reload: Settings → Reload scripts rebuilds the whole Lua state and re-executes every file; Lua globals are cleared.
  • Failure protection: if config.lua fails during a reload, the previous working configuration and plugins are kept. Settings shows at most 100 script warnings.
  • Threading: all Lua callbacks run synchronously on the UI thread — no blocking, no long loops, no network/heavy IO.

4. Plugin file format

A plugin is a plain Lua chunk (not a module — no return needed): the file executes once when loaded, registers callbacks and ends. Recommended shape:

-- plugins/my_plugin.lua
-- 1) one-time setup at the top of the file / 文件顶部初始化
local plays = 0

echoport.log("my_plugin loaded on EchoPort " .. echoport.version)

-- 2) register event hooks / 注册事件钩子
echoport.on("track_start", function(track)
  if track == nil then return end       -- fields may be nil; always nil-check
  plays = plays + 1
  echoport.notify("♪ " .. track.title .. " — " .. track.artist)
end)

-- 3) register custom actions / 注册自定义动作
echoport.actions.add({
  id = "my_stats",                      -- required, unique
  title = "Play count / 播放统计",       -- required
  run = function()
    echoport.notify("tracks played this session: " .. plays)
  end,
})

-- 4) bind a key / 绑定快捷键
echoport.bind("Ctrl+Alt+P", "action:my_stats")

Use local for state (cleared on reload) and helper functions freely; no module() or return table is required. One file per concern keeps debugging simple.

  title = "title",
  artist = "artist",
  album = "album",                -- may be nil
  platform = "youtube",            -- local|spotify|apple_music|netease|soundcloud|bilibili|youtube
  duration = 215.0,                -- seconds, may be nil
  url = "https://...",             -- source page, may be nil
  local_path = "/music/x.mp3",     -- local tracks only, may be nil
}
echoport.on("track_end", function(track)
  if track ~= nil then
    echoport.log("track_end: " .. track.title)
  end
end)

echoport.on("download_done", function(track, path)
  if track ~= nil then
    echoport.toast("saved: " .. track.title .. " -> " .. path)
  end
end)
Lua errors inside a callback are caught: they become a warning plus a log line and do not stop other callbacks or plugins. Every argument may be nil — always nil-check.

7. Key bindings

echoport.bind("Ctrl+Alt+N", "next")            -- built-in action
echoport.bind("Ctrl+Alt+H", "action:hello")    -- custom action
echoport.bind("Ctrl+Alt+D", function()         -- arbitrary function (wrapped as a hidden action)
  echoport.notify("custom binding / 自定义绑定")
end)
  • Modifiers: Ctrl Alt Shift Cmd (Cmd == Ctrl on Windows/Linux), case-insensitive.
  • Built-in actions: play_pause, next, previous, seek_forward, seek_backward, volume_up, volume_down, toggle_queue, toggle_favorite, toggle_shuffle, cycle_repeat, open_search, open_settings, open_home.
  • Duplicate chords: last registration wins with a warning; shortcuts are suppressed while a text field has keyboard focus.
  • Binding to an unknown action:<id>: validated after all files load; if it still does not exist the binding is dropped with a warning (forward declarations within a file are fine).

9. Complete example plugin

Save this as <config_dir>/echoport/plugins/example.lua and use Settings → Reload scripts. It demonstrates playback toasts, in-session history, a custom action, a shortcut and logging. The repository also ships a working examples/plugins/example.lua.

-- EchoPort example plugin / 示例插件
local history = {}

echoport.log("example plugin loaded, EchoPort " .. echoport.version)

-- Toast on track start and remember the last 20 titles
echoport.on("track_start", function(track)
  if track == nil then return end
  echoport.notify("♪ " .. track.title .. " — " .. track.artist)
  table.insert(history, 1, track.title)
  if #history > 20 then
    table.remove(history)
  end
end)

-- Log finished searches
echoport.on("search_done", function(query)
  echoport.log("search finished: " .. tostring(query))
end)

-- Custom action: show recent tracks
echoport.actions.add({
  id = "recent_tracks",
  title = "Recent tracks",
  description = "Example plugin history action",
  keys = "Ctrl+Alt+L",
  run = function()
    if #history == 0 then
      echoport.notify("nothing played yet / 还没有播放记录")
      return
    end
    local shown = {}
    for index = 1, math.min(#history, 5) do
      shown[#shown + 1] = history[index]
    end
    echoport.notify("recent: " .. table.concat(shown, " | "))
  end,
})

-- Bind a function to a key
echoport.bind("Ctrl+Alt+G", function()
  local track = echoport.current_track()
  if track then
    echoport.notify("now playing: " .. track.title)
  else
    echoport.notify("nothing playing / 还没有播放")
  end
end)
About “desktop notifications”: EchoPort offers in-app toasts via echoport.notify; there is no dedicated OS notification API. Because the full Lua stdlib is available you could technically call e.g. os.execute("notify-send ..."), but it blocks the UI thread and is platform-dependent — not recommended unless you know what you are doing.

10. Security & limits

  • Not a sandbox: config files and plugins run locally with your user permissions and the full Lua 5.4 standard library (io, os, load, …). Only install scripts you trust.
  • No networking: echoport.* exposes no network API; open_url simply hands a URL to the browser/system.
  • UI thread: all callbacks run synchronously — never block (long loops, os.execute, heavy file IO freeze the interface).
  • Warning cap: Settings shows at most 100 script warnings; further ones are folded.
  • Isolation: each plugin file runs isolated; one broken file does not affect the others. Plugins cannot override the user's config.lua settings.
  • No hot reload: reloading rebuilds the whole Lua state (globals are lost); there is no per-plugin reload.
  • Duplicates: duplicate action ids keep the last definition with a warning; duplicate chords keep the last registration with a warning; invalid chords/events/actions only warn, never crash.

11. Rust extension point (compiled-in plugins)

For higher performance or access to internal app types, implement the echoport::scripting::Plugin trait and register it in a PluginRegistry. It shares the same ScriptEvent stream as Lua.

use echoport::scripting::{Plugin, PluginHost, PluginRegistry, ScriptEvent};
use echoport::state::Command;

struct AutoShuffle;

impl Plugin for AutoShuffle {
    fn id(&self) -> &str {
        "auto-shuffle"
    }

    fn on_event(&mut self, event: &ScriptEvent, host: &mut PluginHost) {
        if let ScriptEvent::TrackStart(track) = event {
            host.notify(format!("now playing: {}", track.title));
            host.dispatch(Command::ToggleShuffle);   // applied on the next frame
        }
    }
}

// Register once when EchoPortApp is created
let mut rust_plugins = PluginRegistry::with_sender(tx.clone());
rust_plugins.register(Box::new(AutoShuffle));

// Dispatch events next to the Lua dispatch point
rust_plugins.fire(&ScriptEvent::TrackStart(track.clone()));
InterfaceNotes
Plugin::id() -> &strunique id; re-registering the same id replaces the earlier plugin and logs a warning
Plugin::on_event(&mut self, &ScriptEvent, &mut PluginHost)called synchronously on the UI thread; keep it cheap; Rust panics are not caught (Lua errors are)
PluginHost::dispatch(Command)queue an app command (echoport::state::Command), applied next frame
PluginHost::notify(text)in-app toast (same as Lua notify)
PluginRegistry::new() / with_sender(tx) / set_sender(tx)create a registry and connect the event channel
register / fire / plugins / is_empty / lenregister, dispatch, inspect

Lua Scripts is not Send (the Lua state is thread-bound) — keep it on the UI thread. Rust PluginRegistry and its plugins are Send.

12. Troubleshooting

SymptomFix
Plugin does not loadCheck the .lua extension, that it sits in plugins/ and is not a hidden file; read the <file>: <error> warning in Settings.
syntax errorCheck Lua syntax (end, commas, quotes); that file is skipped and the others still load.
Event never firesCheck the event spelling (section 5, lowercase with underscores); events only fire on the matching app state change.
Action missing from Settingsactions.add without run or id is rejected with a warning; check the warnings list.
Shortcut does nothingSuppressed while a text field has focus; check the action name; duplicate chords keep the last registration.
State lost after reloadLua globals are cleared on reload; persist only if needed via echoport.paths.data (careful, usually unnecessary).
UI stuttersDo not block or run long work in callbacks; split it up or move heavy work to a Rust plugin's background thread.
